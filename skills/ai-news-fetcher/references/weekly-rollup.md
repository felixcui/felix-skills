# 一段时间的热点汇总（周报 / 月报）

触发：「基于 AI 早报及收藏的内容，总结上周从周一到周日的热点」这类请求。三种取数来源都要用，且**用脚本聚合，不要手数**。

## 1. 早报存档

`~/work/github/media-conent/source/ai-news/ai-news-YYYY-MM-DD.md`，一天一份，文件名就是日期——周一到周日取那 7 个文件。

- 每日热点段：`### 🔥 今日热点` 下的 `1. ...` 行（一句话式）。
- 分类条目：`### <emoji> <类别>（N 条）` 下的 `N. [标题](url) \`来源\`` —— 正则 `^\d+\.\s*\[([^\]]+)\]\(([^)]+)\)\s*\`([^\`]*)\``。
- **条目是数字列表，不是 `-` / `*` 列表**：按 `[-*]` 匹配会得到 0 条（实测踩过），一律用 `^\d+\.`。
- 逐日统计条数 + 分类分布，写 JSON 落盘后再汇总（不要把多天结果在脑子里合并）。

## 2. 收藏内容（news-collect 入库）

`~/work/github/media-conent/raw/*.md`，**按 mtime 落在窗口内**筛（文件名前缀是入库日期 `YYYY-MM-DD_标题.md`），标题足以判断主题分布；按天计数后按主题归类（如 Skill 生态 / Agent 评测 / 逆向 REA / Harness …）。

## 3. 可选：飞书多维表格

按 `updatetime` 过滤当天/当周时，分页与字段口径不稳定（总量可能返回上限值、当天过滤返回 0）——**以本地 `raw/` 为准**，表格只用于抽查个别记录。

## 定时周报（cron 任务，每周六）

用户定的固定周报形态与临时汇总**不是同一件事**，别互相套用参数：

| 项 | 定时周报 | 临时汇总（上面几节） |
|---|---|---|
| 窗口 | **上周日 → 本周六**（周六 18:00 跑，`今天-6` 到 `今天`） | 上一个自然周 周一 → 周日 |
| 条数 | **按热度 ≤ 20 条**，宁少不凑数，不足 8 条按实际发 | 5~6 条主线 + 逐日 2~4 条 |
| 每条长度 | **60–100 个汉字（硬要求，目标 80）**：不足 60 补源文件事实，超 100 删形容词和背景 | 无下限 |
| 结构 | 五类分节 + 一句话总结 | 总览 / 主线 / 逐日 / 收藏分布 / 数据面 |

- 取数仍是 `~/work/github/media-conent/source/ai-news/ai-news-YYYY-MM-DD.md`，只读本地文件，**不联网、不编造**；某天没有文件就跳过，7 天全无则输出「本周无 AI 日报数据」。
- 五类固定为：🔥 模型与产品 / 💰 资本与人事 / ⚙️ 算力与芯片 / 🚀 应用与生态 / ⚖️ 争议与治理；活动、会议、沙龙、报名、招聘、课程招生一律剔除。
- **跨天同一事件合并成一条**（IPO、人事反转这类常连续三天出现），保留信息量最大 + 最新进展，日期写进句中。
- **字数上下限都是写完要数的**：日报热点本来就短，直接拼接多数不达标；补足靠事实（谁、做了什么、关键数字、影响），不靠形容词。反过来模型很容易写到 150 字以上（实测一轮 20 条落在 96–178 字），**上限 100 字要主动删**——只留「主体 + 动作 + 关键数字」，删掉评价、背景、次要并列项。收尾前用 Python 逐条数汉字并打印 min/max，别凭感觉说「都够」。数字（金额、参数、百分比、名次）是周报最值钱的部分，一个都不能省。
- 纯文本，不要 Markdown 表格、不要 `**` 加粗（飞书与群聊都不渲染表格）。
- 任务 id `0fc3850fb6c4`，投递 **`origin`（创建者的当前会话，即与用户的 DM）**；用户明确说过「不用发到群，发当前会话」。早期版本发 `feishu:oc_8fce…`（「AI助理团队」群），改投递目标后要同步改 prompt 里「发到飞书群」这类措辞，否则模型会自己再调群发。**改时间或窗口口径时必须把 prompt 整段重传**（`cronjob_manage action=update` 只传 schedule 不动 prompt，槽位里写死的「今天减 6 天」会和新的执行时刻对不上）。
- 找不到群 id 时（**仅当用户又要改回发群**）：`lark-cli api GET /open-apis/im/v1/chats --params '{"page_size":50}' --as bot` 列出机器人所在群（返回 `chat_id` + `name`），不要凭名字猜 id。

## 组织（用户偏好）

1. 一句话总览（本周关键词）
2. **5~6 条跨天主线**（同一件事在几天里怎么演进，带日期轨迹）——这是最有价值的部分，不要退化成逐日流水账
3. 逐日最热 2~4 条（周一 → 周日）
4. 收藏侧主题分布（每类一句点评）
5. 数据面：总条数 + 分类合计 + 「其他AI相关」兜底占比
6. 末尾给 2~3 个可选后续（写成飞书文档 / 生成公众号周报草稿，草稿走 felix-wechat-writer 只到草稿箱 / 跑分类抽样核对）

- **飞书消息不支持 markdown 表格**：用 emoji + 加粗列表；分类分布用一行「类别 N | 类别 N」并列，不要贴长表。
- 「其他AI相关」兜底占比是分类器健康度信号，> 20% 时关联一句（注意该列是飞书 AI 字段，见 SKILL.md 的分类说明）。

## 坑点

- **热点段是后加的功能**：早于它上线的存档没有 `### 🔥 今日热点`——那时用当天的分类条目自己挑 2~3 条最热，不要报错、也不要写成「当天没有热点」。
- **先 `date` 定当前日期再倒推窗口**：上下文里的「今天」可能滞后一天以上；用户说的「上周」= 上一个完整自然周（周一 ~ 周日）。
- **逐日条数要对账**：把每天的条数打印出来（如 28/38/40/43/49/45/27），逐日相加与总计一致再写结论——汇总类回答里的数字是硬声明。
- **发布前必须对专有名词做 grep 自查，模型会凭空补奖项和荣誉**：实测一轮 20 条里混进了一条「中国团队拿下戈登贝尔奖」，7 个日报文件里根本搜不到这个词。规则：每条里的奖项、机构、产品名、人名、金额、百分比、日期，都要能在源文件里直接检索到；任一查不到就删掉该项或整条，**不要用「合理推测」补背景**（「某奖五年内第二次回到中国」「某专家曾预测 20XX 年」这类最容易被编出来）。源文件写「据报道/据传闻」的，成稿保留同样的限定词。
- **手动预览别直接用任务默认窗口**：prompt 里的窗口是「今天减 6 天 → 今天」，假定执行日是周六；在工作日用 `cronjob_manage action=run` 试跑会取到错误的 7 天。用 `run` 的 `prompt` 参数把窗口钉死（如「时间窗固定用 2026-11-17 至 2026-11-23」），跑完再回读输出核对字数与事实。
