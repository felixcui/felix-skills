# 一段时间的热点汇总（周报 / 月报）

触发：「基于 AI 早报及收藏的内容，总结上周从周一到周日的热点」这类请求。三种取数来源都要用，且**用脚本聚合，不要手数**。

## 1. 早报存档

`~/work/github/media-conent/source/ai-news/ai-news-YYYY-MM-DD.md`，一天一份，文件名就是日期——周一到周日取那 7 个文件。

- 每日热点段：`### 🔥 今日热点` 下的 `1. ...` 行（一句话式）。
- 分类条目：`### <emoji> <类别>（N 条）` 下的 `N. [标题](url) \`来源\`` —— 正则 `^\d+\.\s*\[([^\]]+)\]\(([^)]+)\)\s*\`([^\`]*)\``。
- **条目是数字列表，不是 `-` / `*` 列表**：按 `[-*]` 匹配会得到 0 条（实测踩过），一律用 `^\d+\.`。
- 逐日统计条数 + 分类分布，写 JSON 落盘后再汇总（不要把多天结果在脑子里合并）。

## 2. 收藏内容（news-collect 入库）

`~/work/github/media-conent/raw/*.md`，**按 mtime 落在窗口内**筛（文件名前缀是入库日期 `YYYY-MM-DD_标题.md`），标题足以判断主题分布；按天计数后按主题归类（如 Skill 生态 / Agent 评测 / 逆向 REA / Harness …）。

## 3. 可选：飞书多维表格

按 `updatetime` 过滤当天/当周时，分页与字段口径不稳定（总量可能返回上限值、当天过滤返回 0）——**以本地 `raw/` 为准**，表格只用于抽查个别记录。

## 组织（用户偏好）

1. 一句话总览（本周关键词）
2. **5~6 条跨天主线**（同一件事在几天里怎么演进，带日期轨迹）——这是最有价值的部分，不要退化成逐日流水账
3. 逐日最热 2~4 条（周一 → 周日）
4. 收藏侧主题分布（每类一句点评）
5. 数据面：总条数 + 分类合计 + 「其他AI相关」兜底占比
6. 末尾给 2~3 个可选后续（写成飞书文档 / 生成公众号周报草稿，草稿走 felix-wechat-writer 只到草稿箱 / 跑分类抽样核对）

- **飞书消息不支持 markdown 表格**：用 emoji + 加粗列表；分类分布用一行「类别 N | 类别 N」并列，不要贴长表。
- 「其他AI相关」兜底占比是分类器健康度信号，> 20% 时关联一句（注意该列是飞书 AI 字段，见 SKILL.md 的分类说明）。

## 坑点

- **热点段是后加的功能**：早于它上线的存档没有 `### 🔥 今日热点`——那时用当天的分类条目自己挑 2~3 条最热，不要报错、也不要写成「当天没有热点」。
- **先 `date` 定当前日期再倒推窗口**：上下文里的「今天」可能滞后一天以上；用户说的「上周」= 上一个完整自然周（周一 ~ 周日）。
- **逐日条数要对账**：把每天的条数打印出来（如 28/38/40/43/49/45/27），逐日相加与总计一致再写结论——汇总类回答里的数字是硬声明。
